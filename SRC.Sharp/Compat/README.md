# 互換性の検証用のシナリオ「トレス島試験記録」

元の SRC（VB5 の Src.exe。Ver.2.2.33）と SRC# の両方で動かし、動作を比べるためのデータパックとシナリオ（#1549。親は #1548）。実機との比較（#1550）・CI での通し実行（#1551）・人による通しプレイ（#1552）・画面と音の見比べ（#1553）は、すべてこのシナリオを使う。

名前・設定・画像・音は、すべてこのリポジトリのために作った。既存の作品・配布物（汎用データ・データパック・シナリオ）は使っていない。

いまあるのは第一話と第二話（間にインターミッション）。残りの話は「[残りの話の計画](#残りの話の計画)」にある。

## 置き場所と構成

`SRC.Sharp/Compat/` に置く。

- `SRC.Sharp/Content/` は SRC#Web の組み込みのカタログで配る遊べるシナリオの置き場所で、ここに置くと配る物と検証用の物が混ざる
- `SRC.Sharp/E2E/` は、フォルダを足すだけで `E2ECorpusTests` のケースになるコーパス（1 ケース 1 機能の小さなシナリオ）の置き場所で、何話もある通しのシナリオは合わない

| 置き場所 | 中身 |
|---|---|
| `torres/` | シナリオのフォルダ。元の SRC にも SRC# にも、このフォルダをシナリオのフォルダとして渡す |
| `torres/ep01.eve`・`ep01.map` | 第一話「試験場の朝」（入口） |
| `torres/ep02.eve`・`ep02.map` | 第二話「錆の巣」。第一話から `Continue ep02.eve` で続く。単体でも始められる（第一話のデータが無ければ部隊を作る） |
| `torres/Lib/include.eve` | 全話共通のイベント（敗北・再開・報酬・章の題）。シナリオを読むときに自動で取り込まれる |
| `torres/Data/` | ローカルデータ（`pilot.txt`・`unit.txt`・`item.txt`・`pilot_message.txt`・`pilot_dialog.txt`・`non_pilot.txt`・`animation.txt`・`effect.txt`）。`@作品名` を使わずに、シナリオのフォルダの `Data` に直接置く（元の SRC の `Event.bas` の「ローカルデータの読みこみ」） |
| `torres/Data/System/` | `sp.txt`・`alias.txt`・`terrain.txt`。SRC 本体の同じファイルの代わりに読まれる（`terrain.txt` は本体のものに足される。番号は 1000 番台で、本体の地形と重ならない） |
| `torres/Bitmap/`・`Sound/`・`Midi/` | 画像（8 ビットの BMP）・効果音（WAV）・BGM（MIDI）。すべて `make_assets.py` が作る |
| `make_assets.py` | 画像・音・BGM・地形データ・マップを作る（Pillow が必要。乱数を使わないので、作り直しても同じになる） |
| `export_sjis.py` | 元の SRC に渡す形（Shift_JIS・CRLF）に書き出す |
| `torres.play` | 第一話から最後まで自動でプレイする手順（`srcsharp play` の PlayScript） |
| `torres-ep02.play` | 第二話を単体で始めて、形態の変化などを決まった手順で確かめる PlayScript |

ファイル名・フォルダ名はすべて ASCII にしている（zip に入れたときや、日本語版でない Windows で名前が化けないように）。

## 文字コード

| 場所 | 文字コード・改行 |
|---|---|
| リポジトリの中（`torres/` のテキスト） | UTF-8（BOM なし）・LF。SRC# はデータとイベントを UTF-8 で読むので、そのまま動かせる。`.gitattributes` で、Windows で取り出しても LF にする |
| 元の SRC に渡すもの（`export_sjis.py` の出力） | Shift_JIS（Windows のコードページ 932）・CRLF。元の SRC はこの形でしか読めない |

テキストには Shift_JIS にできる文字だけを使う。`python3 export_sjis.py --check` が、Shift_JIS にできない文字（U+2212 の「−」、U+00A0 など）・BOM・ASCII でないファイル名があると、ファイルと行を出して失敗する。

## 元の SRC で動かす手順（Windows）

**未確認**：元の SRC（Ver.2.2.33）での動作は、まだ Windows で確かめていない（#1549 の完了の条件。確かめる人と時期は #1548 の「決めること」）。

1. Shift_JIS に書き出す（Python 3 があればどの OS でもよい）

   ```sh
   python3 SRC.Sharp/Compat/export_sjis.py out/torres --zip
   ```

   `out/torres`（と `out/torres.zip`）ができる。中身は `torres/` と同じ並びで、テキストだけが Shift_JIS・CRLF になっている。
2. Windows に `out/torres` を写す。場所はどこでもよい（SRC 本体のフォルダの下でなくてよい）
3. SRC 本体（Src.exe）のフォルダに `Data\System\terrain.txt` があることを確かめる。元の SRC は本体の地形データが無いと起動しない（`SRC.bas`）。中身はどの版の汎用データのものでもよい（このシナリオは 1000 番台の自前の地形だけを使う）。汎用データ・汎用戦闘アニメ・効果音集は要らない
4. Src.exe を起動し、`torres\ep01.eve` を開く。第二話から始めるときは `torres\ep02.eve` を開く
5. 確かめること（#1550 で SRC# と比べる値）
   - 読み込みのエラーが出ないこと
   - 各話の終わりまで進めること
   - 下の「[自動のプレイで確かめている値](#自動のプレイで確かめている値)」が、同じ手順を踏んだときに SRC# と同じになること

元の SRC で確かめていないため、次の点は推定のまま。

- マップファイルの 2 行目（空の行）を、元の SRC の `Input #` が空の値として読むこと（このリポジトリの他のマップと同じ形）
- 64×64 の顔の画像・8 ビットの BMP・カットイン（`animation.txt` のクロスストライク）が表示されること
- シナリオの `Data\System\sp.txt`・`alias.txt` が、SRC 本体の同じファイルの代わりに読まれること（`SRC.bas` の読み込みの順から）

## SRC# で動かす手順

```sh
# lint（SRCDataLinter と同じ検査）。問題が無ければ「問題 0 件」
srcsharp lint SRC.Sharp/Compat/torres

# 第一話から最後まで自動でプレイする（--skip-wait なら数秒）。セーブのファイルを書くので、写したフォルダで動かすとよい
srcsharp play SRC.Sharp/Compat/torres/ep01.eve --script SRC.Sharp/Compat/torres.play --app-path SRC.Sharp/Content/basic-data --skip-wait
# 第二話を単体で始める
srcsharp play SRC.Sharp/Compat/torres/ep02.eve --script SRC.Sharp/Compat/torres-ep02.play --app-path SRC.Sharp/Content/basic-data --skip-wait
```

`--app-path` には SRC 本体のフォルダとして、自作の最小の汎用データ（`SRC.Sharp/Content/basic-data`）を渡す（地形データ・戦闘の効果音・インターミッションのステータス表示の `Lib` が入っている）。

テスト:

| テスト | 内容 |
|---|---|
| `SRCCoreTests` の `E2E/CompatScenarioDataTests` | データ・地形・マップ・イベントが誤り無く読めること。データが指す画像（ユニット・顔・地形）・形態（変形・合体・分離の行き先、合体技のパートナー）・スペシャルパワーが揃っていること |
| `SRCRenderTests` の `CompatScenarioTests` | `torres.play`・`torres-ep02.play` のうち、「ここから最後まで自動で進める」の行の手前（各話の初めの決まった手順と、その結果の確かめ）を流す。最後まで流すと待ち時間（戦闘アニメ・メッセージの表示時間）で数分かかるため、CI では流さない（CI で最後まで流すのは #1551） |

### CI での通しのプレイとゴールデン

CI の `test-compat-scenario`（#1551）が、`tools/compat_play.py` で次のことをする。話（`*.play`）を足しても CI を書き換えなくてよい。

1. `Compat/` の下の、`Data` を持つフォルダを `srcsharp lint` と SRCDataLinter に掛ける。エラーがあれば失敗
2. `Compat/*.play` のそれぞれを、乱数の種を固定して（`srcsharp play --seed 1`）最初から最後まで流す。始めるイベントファイルと `--app-path` は、`*.play` の先頭のコメントの `#   srcsharp play Compat/<フォルダ>/<イベントファイル> --script ... --app-path ...` の行から読む（パスは `SRC.Sharp` からの相対）。シナリオのフォルダは一時フォルダに写して動かす。次のときは失敗にする
   - 例外が起きた、または `expect` が外れた（`expect error none` は、イベントのエラーのダイアログが 1 度でも出たことも失敗にする）
   - シナリオが終わらない（`srcsharp play` の最後の行が `terminated` でない）。上限のターン数は `*.play` の `turns 回数` で決め、その後の `expect finished` で確かめる
3. 各話（イベントファイル）の終わりの状態（`srcsharp play --state`）を書き出し、`Compat/golden/<*.play の名前>.txt` と比べる。同じ種で 2 回流し、2 回とも同じになることも確かめる。書き出すのは、資金・ターン数、味方・ＮＰＣのユニット（HP・EN・位置・パイロット・アイテム）とパイロット（レベル・経験値・気力・SP）、ほかの陣営の数、手持ちのアイテム、グローバル変数、イベントのエラー

```sh
# CI と同じこと（srcsharp・SRCDataLinter は Release でビルドしたものを使う。無ければビルドする）
python3 tools/compat_play.py --repeat 2
# 1 つの *.play だけ流す（lint は省く）
python3 tools/compat_play.py torres.play
# ゴールデンを作り直す（話を足したとき・意図して結果を変えたとき）。差分を PR に載せる
SRC_GOLDEN_UPDATE=1 python3 tools/compat_play.py
```

話を足したら、`*.play` に上の形のコメントの行を書き、`SRC_GOLDEN_UPDATE=1` でゴールデンを作る。ゴールデンが変わったときは、SRC# の変更で乱数の使い方や戦闘の結果が変わっていないか、差分を見て理由を確かめてから作り直す。乱数の系列は元の SRC と合わせていないので、ゴールデンの値は元の SRC の結果ではない（黙って変わっていないことを見るためのもの）。

## 素材の作り方

`python3 SRC.Sharp/Compat/make_assets.py` で作り直せる（Pillow が必要）。

| 素材 | 作り方 |
|---|---|
| 地形の画像（`Bitmap/Map`、32×32） | 地形ごとの地の色と記号（木・山・波・縞・れんが・点など）を描く |
| ユニットの画像（`Bitmap/Unit`、32×32、白が透過色） | 味方は青、敵は赤。機体ごとに形（魚・矢・四角・ひし形・円・船・虫・六角形・盾・星など）と英字 1 文字を変える |
| 顔の画像（`Bitmap/Pilot`、64×64） | 人ごとに背景の色と髪の色、左上に頭文字。錆蟲は機械の顔。表情の差分（笑顔・怒り）は口と眉を変える |
| 効果音（`Sound`） | 正弦波・矩形波・ノコギリ波と、線形合同法の擬似乱数のノイズを数式で合成する（22050 Hz・16 ビット・モノラル） |
| BGM（`Midi`） | 決まった音の並び（メロディとベース）を標準 MIDI ファイルに書く |
| 地形データ・マップ | スクリプトの表（地形）と文字の絵（マップ）から書く |

画像・音は、画像生成AI・音声生成AI・作曲AIを使わず、スクリプトで作った。シナリオ・データ・スクリプトは生成AI の Claude（Anthropic）が書いた。

## 残りの話の計画

全 8 話にする。各話で、上の表の「計画」を次のように入れる。各話の初めのターンは、第一話・第二話と同じく、決まった位置の標的や決まった手順で機能を通し、`expect` で確かめられるようにする。

| 話 | 題（仮） | 地形 | 入れる機能 |
|---|---|---|---|
| 第三話 | 霧の水路 | 浅瀬・深い水路・断崖・防壁 | 水中・水上の移動、地形適応が複数あるユニット（`地形適応`）、ＺＯＣとＺＯＣ無効化（防壁の狭い通路）、パーツ分離、ユニットのコマンドでの母艦への着艦と発進、ForEach・Sort（撃破の記録を並べる）。前のインターミッションで乗り換え（千草リンをサポートに乗せる） |
| 第四話 | 空の回廊 | 空・断崖 | 空中、テレポート（ヒバリ）・ジャンプ、ハイパーモード・ノーマルモード、追加パイロット・暴走時パイロット、必要技能の「!」の条件と男性・女性、エリアスで別名を付けた能力の発動 |
| 第五話 | 地下坑道 | 坑道・床 | 地中、召喚と召喚解除、属性（固・連・吸・減・奪）、先制攻撃、統率（ノアが覚える）。前のインターミッションで換装 |
| 第六話 | 月の裏 | 宇宙・暗礁・月面 | 宇宙、追加サポート、改造（インターミッション）、`Load`（敵のデータを `Data\作品名` に分けて読む） |
| 第七話 | 錆の母 | すべて | これまでの機能の組み合わせ（合体した機体の合体技、マップ攻撃と援護の組み合わせ）、クリアデータの引き継ぎの確認（話をまたいだ変数・アイテム・形態） |
| 第八話 | 試験の終わり | 学舎 | 短い終話。エンディング |

セーブは、各話の決まったターン（例：2 ターン目の味方のフェイズ）で中断セーブとクイックセーブを作り、そこから再開して再開のラベルが動くことと、再開の前後で上の「確かめている値」が変わらないことを確かめる場面を入れる。PlayScript から中断・クイックセーブを作る手順は、第三話を作るときに決める。

**SRC#でシナリオ・データを作る**

SRC# でシナリオやデータを作るときの道具と、作り始めてから公開するまでの流れです。データとイベントの書き方そのものは「[データを作成する前に](データを作成する前に.md)」「[シナリオを作成する前に](シナリオを作成する前に.md)」からの各章を見てください。

## まずはブラウザで（かんたん作成）

インストールせずに、好きな作品のキャラを好きな場面で戦わせるシナリオを作って、すぐに遊べます。SRC#Studio（[https://src.koudenpa.net/studio/](https://src.koudenpa.net/studio/)。開発版は [https://7474.github.io/SRC/studio/](https://7474.github.io/SRC/studio/)）の「かんたん作成」を開きます。

1. **作品を選ぶ**: 作品の名前で探して選びます。公開されているデータ（[SRC-Data](https://github.com/7474/SRC-Data) の GSC データパック）を使います
2. **味方と敵を選ぶ**: ユニットとパイロットを名前の候補から選び、レベルを決めます
3. **場面を決める**: マップを選び（平地・サンプルの場面・手元の `.map`）、ユニットをクリックで置きます。サンプルの場面には、おすすめの置き場所や、作品・セリフまで入ったものもあります
4. **セリフを書く**: 戦闘の前・勝ったとき・負けたときの会話を書きます。戦闘中のセリフは、選んだパイロットのデータのものが出ます
5. **出来事を足す**（足さなくてもよい）: 勝ちの条件（敵の全滅・指定した敵を倒す・決まったターン守りきる・指定のマスに着く）と負けの条件を選び、戦闘中の援軍・会話（2 人が戦うとき・HP が減ったとき・落ちたとき・決まったターン）・撤退を足します。作ったシナリオでは、どれも普通のイベント（`ターン`・`破壊`・`攻撃`・`損傷率` など）になっているので、VS Code で開くと書き方の見本になります
6. **遊ぶ**: 「SRC#Web で遊ぶ」で、そのまま SRC#Web で始まります。もう一度遊ぶときは SRC#Web の一覧から選べます

画面の上の「＋ 話を足す」で、話を並べたシナリオにもできます。勝つと次の話へ進み、前の話に出た味方は次の話でも続けて出ます（機体を変えれば乗り換えます）。

「zip で保存」で、作ったシナリオ（イベント・マップ・作品のデータ）を保存できます。中身は `srcsharp new` で作るひな形と同じ形で、README.md に「次にやること」を書いてあります。展開したフォルダは、下の道具（VS Code など）でそのまま開いて続きを書けます。

## 道具

おすすめは VS Code 拡張です。書く・見る・マップを描く・試す・検査するが 1 つの画面でつながります。下の道具はどれも VS Code を使わずに単独でも使えます（ブラウザの SRC#Studio、コマンドラインの `srcsharp`）。

| 道具 | できること |
|---|---|
| VS Code 拡張「SRC# Authoring」 | イベント・データの書き間違いをその場で知らせる、コマンドとラベルの補完、ラベルへ移動、画面付きでイベントを動かす・止めて調べる（デバッガ）、直しながら遊ぶ（ホットリロード）、自動プレイ、マップ作成ツール（下の SRC#Studio と同じもの。イベントの座標の行からマップで見る）、データのプレビュー・表で直す・比べる、試し戦闘、話の強さを確かめる、出来事をフォームで足す、シナリオの見通し（出来事・台本・変数・登場人物）、話のつながりの図、イベントの流れの図、会話や戦闘アニメ・特殊効果のプレビュー、素材の一覧 |
| SRC#Studio | 上の「かんたん作成」。マップ（`.map`）を描く（自動接続）。イベントのユニットの配置をマップで見て動かす、ユニットを動かしながら会話する場面（人形劇）を一手ずつ見て書く・その場面だけ再生する。データのプレビュー・表で直す・比べる。素材の一覧。ブラウザで [https://src.koudenpa.net/studio/](https://src.koudenpa.net/studio/)（開発版は [https://7474.github.io/SRC/studio/](https://7474.github.io/SRC/studio/)）を開くか、VS Code で `.map` のファイルを開く。詳しくは「[マップデータ](マップデータ.md)」 |
| `srcsharp`（コマンドライン） | ひな形を作る（`new`）、試し戦闘のイベントを作る（`trial`）、素材が揃っているかを調べる（`assets`）、話のつながりの図を出す（`flow`）、シナリオの見通しを出す（`outline`）、出来事を書く（`event-text`）、イベントの流れの図を出す（`event-flow`）、会話を画像で確認する（`talk-preview`）、戦闘アニメ・特殊効果を試す（`anime-preview`）、データとイベントを検査する（`lint`）、画面なしで最後まで自動で遊ぶ（`play`）、話の強さを確かめる（`playtest`）、能力値の一覧（`balance`）、このヘルプを引く（`help`） |
| SRC#Avalonia・SRC#Web | 作ったシナリオを遊ぶ（「[SRC#のインストール](SRCSharpのインストール.md)」） |
| データビューア | 公開されているデータ（[SRC-Data](https://github.com/7474/SRC-Data) の GSC データパックなど）を、画像付きで見る・ユニットとパイロットを比べる（[https://7474.github.io/SRC/](https://7474.github.io/SRC/)）。データを作るときの参考に |

VS Code 拡張と `srcsharp` は、.NET 10 SDK を入れてから入れます。

```
dotnet tool install -g SRCSharpTools
```

VS Code 拡張は、拡張機能の画面で「SRC# Authoring」を探して入れます。`srcsharp` が無ければ、拡張が入れるかを尋ねます。

## 汎用データ

シナリオを動かすには、地形データなどの汎用データ（SRC のフォルダの `Data\System` など）が要ります。

- 元の SRC のフルパッケージの汎用データ（「[SRCのインストール](SRCのインストール.md)」）
- SRC# の最小の汎用データ（[SRC.Sharp/Content/basic-data](https://github.com/7474/SRC/tree/master/SRC.Sharp/Content/basic-data)。地形・スペシャルパワー・ユニットの画像・効果音・BGM の最小限。CC0）

VS Code 拡張では、設定の `srcsharp.appPath` にそのフォルダを書きます（拡張の「SRC#」のパネルから選べます）。

## 流れ

### 1. ひな形を作る

VS Code のコマンド「SRC#: 新しいシナリオを作る」か、コマンドラインで作ります。

```
srcsharp new 私のシナリオ --title "私のシナリオ"
```

次のファイルができます。最小の汎用データでそのまま遊べる 1 話です。

| ファイル | 内容 |
|---|---|
| `第1話.eve` | イベント。プロローグ・スタート（マップを出してユニットを置く）・勝ち負けのイベント |
| `第1話.map` | マップ |
| `Data/robot.txt`・`Data/pilot.txt` | ユニット・パイロットのデータ |
| `第1話.play` | 最後まで自動で遊ぶ手順 |
| `.vscode/launch.json` | VS Code で F5 を押すと、開いているイベントを画面付きで動かす |
| `.github/workflows/src-check.yml` | GitHub に置くと、データの検査と、最後まで自動で遊べるかの確かめを毎回行う |

#### 複数話（長編）を作る

`--episodes` に 2 以上の話数を指定すると（VS Code の「新しいシナリオを作る」では話数の入力欄に入れます）、各話とインターミッション・共通イベントが付いた複数話のひな形ができます。

```
srcsharp new 私のシナリオ --title "私のシナリオ" --episodes 3
```

1 話のファイルに加えて、次のファイルができます。

| ファイル | 内容 |
|---|---|
| `Lib/include.eve` | 全話で自動取り込みされる共通イベント（敗北処理・章題・報酬・単体で始めたときの仮部隊 `単体の部隊`） |
| `Lib/作戦会議.eve` | インターミッションのメニュー「作戦会議」から呼ばれるイベント（終わりに引数無しの `Continue` を置いて戻る） |
| `第1話.eve`〜`第N話.eve` | 各話のイベント。第1話〜第(N-1)話は `Continue 第{i+1}話.eve` と `エピローグ:` で次へつなぎ、最終話は `GameClear` で終わる |
| `第1話.map`〜`第N話.map` | 各話のマップ |
| `第1話.play`〜`第N話.play` | 各話を単体でテストする自動プレイ手順（中間話は `holdlist コマンド` でインターミッションまで遊ぶ） |
| `全話.play` | 第1話から最終話まで通しで最後まで遊ぶ手順（`choose コマンド 次のステージへ` で各話をつなぐ） |

複数話を作るときの要点は次のとおりです。

- **第2話以降も単体でテストできるようにする**: `第2話.eve` などの `スタート:` で `If IsDefined(主人公, パイロット) = 0 Then Call 単体の部隊 2 EndIf` のように書いておくと、第1話から通さずにその話のファイルだけを F5 で起動しても、その話に合う部隊を作ってすぐ試せます
- **共通イベントは `Lib/include.eve` にまとめる**: 敗北処理や章タイトル・報酬・味方部隊の定義などを全話で使い回せます
- **マップを置く前に `Launch`**: 前の話から引き継いだ味方は第2話以降では `Create` ではなく `Launch` で出撃させます

### 2. 書く

イベントとデータは VS Code で書きます。保存しなくても、書き間違い（コマンドの引数・`If` と `EndIf` の対応・飛び先のラベルが無い・データの読み込みの誤りなど）に波線が付きます。コマンドとラベルは補完でき、ラベルは F12 で定義へ移動できます。ユニット・パイロット・変数・ラベルの名前は、F2 でシナリオ全体（イベントとデータ）を一度に変えられます（会話の文の中の名前は変えません）。データは「[データ形式](データ形式.md)」から各データの章を見てください。

### 2.5. データを見る・試す

- 公開されているデータを参考にしたいときは、データビューア（[https://7474.github.io/SRC/](https://7474.github.io/SRC/)）のユニット・パイロットのカードの「このデータをコピー」や「VS Code で追加」から定義ブロックをそのまま取り込めます
- データのファイル（`robot.txt`・`pilot.txt` など）を開いて「SRC#: データのプレビュー」を選ぶと、カーソルのあるユニット・パイロットを、ゲームの数値（能力値・特殊能力・武器・スペシャルパワー）で横に出します。保存しなくても、打つたびに変わります。「表で直す」で能力値・地形適応・武器・アビリティを表形式で直せます。ブラウザの [SRC#Studio](https://7474.github.io/SRC/studio/) の「データのプレビュー」でも使えます
- 「SRC#: 試し戦闘」を選ぶと、ユニット・パイロットと敵を選んで、小さなマップで戦わせられます。戦いながらデータを直して保存すると、その場で読み直します。コマンドラインでは `srcsharp trial <シナリオのフォルダ> --unit ユニット` で試し戦闘のイベントを作れます

### 3. マップを描く

`第1話.map` を VS Code で開くとマップ作成ツールが開きます。左クリックで描き、右クリックで地形を拾います。マップの大きさは「大きさ」で変えます。「自動でつなぐ」を入れて道・川・橋・海を描くと、境目のマップチップを自動で選びます。ブラウザの [SRC#Studio](https://7474.github.io/SRC/studio/) でも同じことができます。

- **ユニットの配置**: 「配置」に切り替えると、イベントの `Create`・`Launch`・`Move` などのユニットをマップに重ねて出します。出来事（`ターン 2 敵` など）で出る援軍は破線の枠と出来事の名前で、`進入` の目標のマスは黄色の旗で分けて出します。ドラッグすると、その行の座標だけを書き換えます。VS Code では、イベントの座標のある行にマウスを置いて「マップの上で見る」からも開けます
- **人形劇（ユニットを動かしながら会話する場面）**: 「配置」の「人形劇」で場面（ラベル）を選ぶと、命令を一手ずつ進めて、その時点で誰がどこにいるかと会話を並べて見られます。ユニットをドラッグすると、その手の後に `Move` を書き足します（会話の途中なら会話を切って挟みます）。動かしたいマスが埋まっている・入れない地形なら、元の SRC と同じ規則で近くのマスにずれることや、まだ出ていないユニットを動かしている・話させていることを知らせます
- **場面の再生**: 人形劇の「この場面を再生」で、選んだ場面だけを実際のゲームで流して確かめられます（ブラウザは SRC#Web、VS Code は画面付きのデバッガ）。プロローグからは設定だけを持ってきて、スタート以外の場面ではスタートの配置をしてから始めます

### 3.5. 話のつながり・イベントの流れ・会話を確かめる

複数話や分岐が増えてきたら、VS Code の「SRC#: 話のつながりの図を表示」（イベントエディタ右上のボタン・操作パネル）を開きます。`Continue`・`次ステージ`・`Exec`・`IntermissionCommand`・`Load`・`GameClear` と `If`/`Switch` の分岐をたどり、話の流れの図を出します。矢印には分岐の条件（`If` の式・`Switch` の値）を、話には加わる味方（＋）と抜ける味方（－）を添えます。図のノードや矢印をクリックすると、該当する `.eve` ファイルの行へ飛びます。

コマンドラインでも Mermaid・Markdown・JSON で出せます。

```
srcsharp flow . --format md
```

- **出来事を足す**: イベントファイルを開いて「SRC#: 出来事を足す」を選ぶと、きっかけ（N ターン目・2 人が戦うとき・損傷率・落ちたとき）、会話（話す人とセリフ）、撤退をフォームで選び、かんたん作成と同じ書き方のイベント（`ターン 3 味方:` などのラベルと、何をするかの注釈）をファイルの最後に足します。名前はそのファイルに出てくる人から選べ、シナリオに出てこない相手は知らせます。足したあとは普通のイベントなので、そのまま書き足せます（元に戻すこともできます）
- **シナリオの見通し**: 「SRC#: シナリオの見通し」（コマンドラインは `srcsharp outline`）で、話ごとの部隊と登場人物（加入・離脱・話す人の行数）、出来事の一覧（いつ起きて何をするか）、変数（どこで設定し、どこで読むか）、台本（会話を話の順に）を 1 枚にまとめます。起きない出来事（出てこない相手の `破壊` など）、設定するだけの変数、1 文字違いの変数、勝ちの終わり方が無い話も知らせます。この気づいたことは、イベントを開いた・保存したときに VS Code の問題パネルにも情報として出ます（設定「srcsharp.outlineFindings」で切れます）。どれも行へのリンクから該当の場所へ飛べます
- **イベントの流れの図**: 1 つのイベントファイル（と `Include`・`Require` 先）の中で、発火イベント・ラベル・`Call`・`Goto`・`Require` がどうつながっているかは、VS Code の「SRC#: イベントの流れの図を表示」（コマンドラインは `srcsharp event-flow <イベントファイル>`）で確かめられます。ノードをクリックするとその行へ飛びます
- **会話のプレビュー**: `*.eve` の `Talk`・`AutoTalk` にカーソルを置いて VS Code の「SRC#: 会話をプレビュー」（コマンドラインは `srcsharp talk-preview <イベントファイル> --line 行`）を開くと、シナリオを遊ばずに実際のメッセージウィンドウと同じ折り返し・顔グラフィック・改ページを確認できます
- **戦闘アニメ・特殊効果のプレビュー**: `animation.txt`・`ext_animation.txt`・`effect.txt` や `Lib/汎用戦闘アニメ` の `*.eve` で VS Code の「SRC#: 戦闘アニメ・特殊効果をプレビュー」（コマンドラインは `srcsharp anime-preview <ファイル> --line 行 --play-once`）を選ぶと、選んだ攻撃側・防御側で 1 回再生して確認できます。直して保存した後は「戦闘アニメ・特殊効果をもう一度再生」でそのまま確認し直せます

### 4. 試す

- イベントを開いて F5（「開いているイベントを遊ぶ（画面付き）」）。VS Code の中のタブで遊べます。行の左をクリックするとブレークポイントを置け、止まったところで変数を見られます
- 遊んでいる最中にイベント・データ・画像を直して保存すると、遊んでいる状態のまま読み直します（ホットリロード）
- 「第1話 を自動で最後まで」や「全話を自動で通しプレイ」で、`.play` の手順のとおり自動で遊びます。勝つまでの流れや複数話のつながりが壊れていないかを確かめられます
- **途中の話から遊ぶ**: 話を開いて「SRC#: この話から遊ぶ」を選ぶと、前の話までを遊んだ状態（部隊・レベル・資金・変数）からその話を画面付きで始めます。状態は、通しの自動プレイ（`全話.play`）がインターミッションのたびに `.srcsharp/episodes/第N話.srcs` に残します（無ければ、その場で通しの自動プレイを動かして作ります）
- **強さを確かめる**: 話を開いて「SRC#: この話の強さを確かめる」（コマンドラインは `srcsharp playtest 第1話.eve`）を選ぶと、乱数を変えて何回か自動で遊び、勝ち・負け・時間切れの回数、かかったターン数、落ちた味方と、直し方の手がかり（敵のレベルを少し下げる、など）を表にします。自動で遊ぶ AI は人より弱いので、「人ならこれより勝ちやすい」目安として見てください

### 5. 検査する・素材を確かめる

```
srcsharp lint . --app-path <汎用データのフォルダ>
```

読み込めないデータ・イベントの誤りを出します。`--rules` で書き方の決まり（GSC データパックの基準など）も調べられます（`srcsharp lint --list-rules`）。ひな形の `.github/workflows/src-check.yml` は、GitHub に push するたびにこの検査と自動プレイを動かし、結果をプルリクエストに出します。

シナリオに必要な画像・音・マップが揃っているかは、VS Code の「SRC#: 素材の一覧（揃っているか）を表示」、ブラウザの [SRC#Studio](https://7474.github.io/SRC/studio/) の「素材の一覧」タブ、またはコマンドラインで確かめられます。

```
srcsharp assets . --app-path <汎用データのフォルダ>
```

参照している素材と参照場所（ファイルと行）、SRC と同じ検索順（シナリオ → 拡張データ → SRC 本体）で見つかった場所・見つからないもの、式で組み立てるため確かめられない参照、シナリオ内で参照されていないファイルを並べます。`--format readme` で README に書く「必要な素材」の下書きを作れ、`--fail-on-missing` を付けると不足があるときに終了コード 1 を返します。

### 6. 公開する

- SRC#Web で遊べるように置く: 「[SRC#Webの使い方](SRCSharpWebの使い方.md)」
- 元の SRC と同じく、フォルダを zip にして配る

## 困ったとき

- コマンド・関数・データの書き方は `srcsharp help 項目`（例: `srcsharp help Talk`）でも引けます
- 動きがおかしいときは、デバッガで止めて変数を見るか、「[ログ](ログ.md)」を見てください

# 元の SRC のセーブデータの形式

> 記録として残している文書です（2026-11 時点。7474/SRC#1577）。元の SRC（VB5。`SRC/SRC_20121125`）のセーブデータ（クリアデータ・中断データ）を、書き出しと読み込みの手続きから読み取ってまとめた。

元の SRC は、クリアデータ（インターミッションの「データセーブ」）と中断データ（マップのコマンドの「中断」・クイックセーブ・リスタート用のデータ）を、どちらも拡張子 `.src` のテキストファイルに書く。SRC# は JSON で書き、クリアデータを `.srcs`、中断データを `.srcq` にしている（書き出しは今も JSON だけ）。

## 共通の書き方

- 文字コードは Shift_JIS（日本語版の Windows のコードページ 932）、改行は CR+LF
- 書くのは VB の `Write #` 文。1 回の `Write #` が 1 行になり、値はカンマで区切る
  - 文字列は `"` で囲む。中の `"` はそのまま書く（二重にしない）
  - 数値は引用符なしで書く（小数点は `.`）。`Format$` で作った値は文字列なので `"` で囲まれる（変数の値）
  - 真偽値は `#TRUE#`・`#FALSE#`
- 読むのは `Input #`（カンマか行の終わりまでを 1 つの値として読む。`"` で囲まれていれば次の `"` まで）と `Line Input #`（行の残りを全部読む）。値を読み飛ばすところは `Line Input #` で 1 行ずつ飛ばす
- 版（`SaveDataVersion`）は、書いた Src.exe の版を `10000 * Major + 100 * Minor + Revision` で表した数（Ver.2.2.33 なら 20233、Ver.2.4.0 なら 20400）。読むときにこの値で古い形式を読み替える
- 起動の引数で `.src` を開いたとき、元の SRC は中身で種類を決める（`SRC.bas` の `Main`）。最初の値が数値で 10000 より大きければ次の値も読み、その値が数値ならクリアデータ（タイトルの数）、数値でなければ中断データ（シナリオのファイル名）

## クリアデータ（`SRC.bas` の `SaveData`・`LoadData`）

| 行 | 中身 | 書く手続き |
|---|---|---|
| 1 | 版 | `SaveData` |
| 2 | 使う作品（タイトル）の数 n | |
| 3〜 | 作品名（n 行） | |
| | 次ステージ（変数「次ステージ」の値） | |
| | 総ターン数（`TotalTurn`） | |
| | 資金（`Money`） | |
| | `0`（パーツ用のダミー） | |
| | グローバル変数 | `Event.bas` の `SaveGlobalVariables` |
| | パイロット | `Pilots.cls` の `Save` |
| | ユニット | `Units.cls` の `Save` |
| | アイテム | `Items.cls` の `Save` |

- グローバル変数: 1 行目に数、続けて 1 つ 1 行で `"名前","値"`。数値の変数も `Format$` の文字列で書くので、`"名前","123"` になる
- パイロット（追加パイロット・追加サポートは書かない）: 1 行目に数、続けて 1 人 3 行
  1. 名前。名前とＩＤが違うときは `"名前 ＩＤ"`（空白で区切った 2 つの要素）
  2. レベル, 経験値
  3. 乗っているユニットのＩＤ。乗っていなければ `"-"`、`Leave` されていれば `"離脱"`
- ユニット: 1 行目にＩＤ作成用カウンタ（`IDCount`）、2 行目に数、続けて 1 機ごとに
  1. 名前
  2. ＩＤ, ランク, 状態（`Status`）
  3. 他形態の数と、他形態のＩＤ（1 つ 1 行）
  4. パイロットの数と、パイロットのＩＤ（1 人 1 行）
  5. サポートの数と、サポートのＩＤ（1 人 1 行）
  6. アイテムの数と、アイテムのＩＤ（1 つ 1 行）
- アイテム: 1 行目にＩＤ作成用カウンタ、2 行目に数、続けて 1 つ 2 行（名前 / ＩＤ, 装備しているユニットのＩＤ（無ければ `"-"`））

`LoadData` の読み方:

1. 版を読む。10000 より大きくなければ、それは作品の数（版を書かなかった古い形式）
2. 作品ごとに `IncludeData` し、シナリオのフォルダの `Data` のローカルデータを読む
3. 次ステージ・総ターン数・資金・ダミーを読み、`LoadGlobalVariables` でグローバル変数を全部置き換えてから「次ステージ」を設定する
4. パイロット（`Pilots.Load`）: 名前で `PList.Add(名前, レベル, "味方", ＩＤ)` してから経験値を設定する。名前が定義されていなければ、`(` より前で探し直し、それでも無ければ「〜のデータが定義されていません」で終わる。乗っているユニットは読み飛ばす
5. ユニット（`Units.Load`）: 新しいユニットに名前・ＩＤ・ランク・陣営（味方）・状態を設定して全回復する。他形態・パイロット・サポート・アイテムは読み飛ばす
6. アイテム（`Items.Load`）: 名前とＩＤだけを設定する。ファイルの終わりなら読まない（アイテムを書かなかった古い形式）
7. ファイルを開き直して先頭から読み飛ばし（グローバル変数は 2 つ目の「パーツ用のダミー」の `Input #` で数を読み、その行数を飛ばす）、つながりを戻す（`LoadLinkInfo`）
   - パイロット: `"離脱"` なら `Away` を立てる。ユニットのＩＤで `UList` にあれば乗せる（`Unit` を設定する）。無ければ、ＩＤの `:` より前のユニットを作って `Ride` する
   - ユニット: 他形態（`AddOtherForm`）・パイロット（`AddPilot`。ユニットが `離脱` ならパイロットも `Away`）・サポート（`AddSupport`）・アイテム（装備していないアイテムを `CurrentForm.AddItem0`。`IList` に無くアイテムデータがあれば作って付ける）を戻し、最後に全ユニットを `Update True` する
   - アイテム: 読み飛ばすだけ
8. 全ユニットを `Reset` し、システム側のイベントデータ（`LoadEventData ""`）を読む

## 中断データ（`SRC.bas` の `DumpData`・`RestoreData`）

| 中身 | 書く手続き |
|---|---|
| 版 | `DumpData` |
| シナリオのファイル名（シナリオのフォルダからの相対パス） | |
| 使う作品の数 n と、作品名（n 行） | |
| ターン数（`Turn`）・総ターン数・資金（1 つ 1 行） | |
| イベントのデータ | `Event.bas` の `DumpEventData` |
| パイロット | `Pilots.cls` の `Dump`（`Pilot.cls` の `Dump`） |
| アイテム | `Items.cls` の `Dump`（`Item.cls` の `Dump`） |
| ユニット | `Units.cls` の `Dump`（`Unit.cls` の `Dump`） |
| マップ | `Map.bas` の `DumpMapData` |
| ＢＧＭのファイル名（`Midi` のフォルダからの相対パス） | `DumpData` |
| 連続演奏・固定・ボス用（`RepeatMode`・`KeepBGM`・`BossBGM`。1 つ 1 行） | |
| 乱数系列（`RndSeed`・`RndIndex`。1 つ 1 行） | |

- イベントのデータ: グローバル変数・ローカル変数（どちらも上の形）、イベントのラベルの数と有効・無効（`colEventLabelList` の順に `#TRUE#`・`#FALSE#` を 1 つ 1 行）、`Require` で読んだイベントファイルの数とファイル名（1 つ 1 行）
- パイロット（追加パイロットは書かない。追加サポートは書く）: 1 行目に数、続けて 1 人 5 行
  1. 名前, ＩＤ, 陣営
  2. レベル, 経験値
  3. ＳＰ, 気力, 霊力
  4. 生きているか, `Leave` されているか, サポートとして乗った順番
  5. 乗っているユニットのＩＤ（無ければ `"-"`）
- アイテム: 1 行目に数、続けて 1 つ 2 行（名前, ＩＤ, 存在しているか / 装備しているユニットのＩＤ（無ければ `"-"`））
- ユニット: 1 行目に数、続けて 1 機ごとに
  1. 名前, ＩＤ, 陣営（`Party0`）
  2. ランク, ボスランク, Ｘ, Ｙ
  3. 場所（`Area`）, 使った行動数, 思考モード（`Mode`）, 状態（`Status`）
  4. ご主人様のＩＤ（無ければ `"-"`）
  5. 召喚主のＩＤ（無ければ `"-"`）
  6. サポートアタック・サポートガードの使用回数
  7. 同時援護攻撃・カウンター攻撃の使用回数
  8. 他形態・格納したユニット・パイロット・サポートの、それぞれ数とＩＤ（1 つ 1 行）
  9. 追加サポートのＩＤ（無ければ `""`）
  10. 召喚したユニット・アイテムの、それぞれ数とＩＤ
  11. 掛かっているスペシャルパワーの数と、`"名前","データ"`（1 つ 1 行）
  12. 特殊状態の数と、`"名前",残りターン,レベル,"データ"`（1 つ 1 行）
  13. 武器の数と残弾数、アビリティの数と残り使用回数（1 つ 1 行）
  14. ＨＰ, ＥＮ
- マップ: `"マップのファイル名","描画方法"`（描画方法は「マップ限定」のとき `描画方法(マップ限定)`）、幅, 高さ、マスごと（Ｘの順に、その中でＹの順）に `地形番号,画像番号`、表示位置 `MapX,MapY`、`"Layer"` の行、マスごとに `上層の地形番号,上層の画像番号,マスのデータの種類`
  - マップのファイル名は、シナリオのフォルダの中ならシナリオのフォルダからの相対パス、外なら絶対パス

`RestoreData` の読み方:

1. 最初の値が数値なら版として読み、次の値をシナリオのファイル名として読む。数値でなければ版を 1 とし、それをシナリオのファイル名とする
2. シナリオのファイル名がいまと違えば、ウィンドウのタイトルを変え、イベントデータを読み直す
3. クイックロードでなければ、作品ごとに `IncludeData` し、ローカルデータとイベントデータ（`LoadEventData シナリオ, "リストア"`）を読む。クイックロードなら作品名は読み飛ばす
4. ターン数・総ターン数・資金を読む
5. `RestoreEventData`: グローバル変数・ローカル変数を全部置き換える。ラベルの有効・無効を読んでおき、`Require` のファイルを読んでから、ラベルに順に設定する（保存した数より多いラベルは有効にする）
6. パイロット・アイテム・ユニットを全部消して作り直す（`Restore`）。パイロットは名前・レベル・経験値・ＳＰ・気力・霊力などを設定し、ユニットはランク・位置・状態・パイロット・サポート・追加サポート・スペシャルパワー・特殊状態・ＨＰ・ＥＮを設定する（ほかのユニット・アイテムとのつながりは後で戻す）
7. `RestoreMapData`: マップを戻す。マップのファイル名・描画方法・大きさ・地形・レイヤのどれかが変わっていれば、背景を書き直す（`IsMapDirty`）。`"Layer"` の行が無ければ、その値をＢＧＭのファイル名として返す
8. ＢＧＭを `Midi` のフォルダで探す。見つかれば演奏し、連続演奏・固定・ボス用を読む。見つからなければＢＧＭを止め、3 行を読み飛ばす
9. オプション「デバッグ」「乱数系列非保存」が無く、ファイルの終わりでなければ、乱数系列を戻す
10. ファイルを開き直して先頭から読み飛ばし（イベントのデータは `SkipEventData`）、つながりを戻す（`RestoreLinkInfo`）
    - パイロット: 乗っているユニット
    - アイテム: 装備しているユニット（`UList` にあれば）
    - ユニット: ご主人様・召喚主・他形態・格納したユニット・召喚したユニット・アイテム（`AddItem0`）を戻し、`Update True` してから、武器の残弾数（`SetBullet`）・アビリティの残り使用回数（`SetStock`）・ＨＰ・ＥＮを設定する
11. もう一度開き直し、パラメータを戻す（`RestoreParameter`）。霊力やＨＰ・ＥＮは最大値が特殊能力で変わるので、特殊能力の設定が終わってから設定し直す
    - パイロット: ＳＰ・気力・霊力
    - ユニット: ＨＰ・ＥＮを設定してから `Update`
12. `PList.UpdateSupportMod`。背景を書き直す必要があれば書き直して「再開」のイベントを起こす。ターンが 0 なら「スタート」のイベントと味方フェイズを始め、そうでなければ味方フェイズのユニットの選択に戻る

## 版による違い

| 版 | 違い | 読み替え（元の SRC） |
|---|---|---|
| 版を書いていない（クリアデータ） | 1 行目が作品の数 | 版が 10000 以下なら、その値を作品の数とする（`LoadData`） |
| 版を書いていない（中断データ） | 1 行目がシナリオのファイル名 | 版を 1 とする（`RestoreData`） |
| 10700 未満 | ユニットのＩＤが「名前+数」（`:` が無い） | `ConvertUnitID` で「名前:数」にする（クリアデータのユニット・パイロットの乗っているユニット。他形態のＩＤは版によらず変換する） |
| 10724 未満 | `SetSkill` の変数（`Ability(…)`）がエリアスに対応していない | 能力名をエリアスの最初の能力に置き換える（グローバル変数） |
| 10730 未満 | ラーニングした特殊能力が使えない不具合 | 個々の能力の `Ability(名前,能力)` があれば、`Ability(名前)` を定義する（グローバル変数） |
| 10731 未満 | 非表示能力への不要な `SetSkill`。`ClearSkill` の不具合で作られた変数 | `Ability(…,非表示)` のグローバル変数を読まない。名前と値が同じ `Ability(…)` のローカル変数を読まない |
| 10732 未満 | 能力の一覧に非表示能力と重複がある | `Ability(名前)` の値から「非表示」と重複を除く（グローバル変数） |
| 10741 未満 | 「パイロット能力付加」「パイロット能力強化」を特殊状態で持っていた | その特殊状態を読まない（中断データのユニット） |
| 20003 以下 | `Require` のイベントファイルを書いていない | 読まない（`RestoreEventData`・`SkipEventData`） |
| 20027 未満 | エリアスの能力を `SetSkill` すると、エリアスの解説が無効になる不具合 | `Ability(…)` の値が `0 解説 …` なら、レベルを `DEFAULT_LEVEL` にする（グローバル変数） |
| 20210 未満 | ユニットの追加サポートを書いていない | 読まない（`Unit.Restore`・`RestoreLinkInfo`・`RestoreParameter`） |
| 版によらず | マップのレイヤ（`"Layer"` の行から）は Ver.2.4.0 の手直し（`240a`）で足したもの | `"Layer"` の行があるときだけ読む。Ver.2.2.33 の Src.exe はレイヤを書かないと読んだ（推定。2.2.33 のソースは無い） |
| 版によらず | 乱数系列は後の版で足したもの | ファイルの終わりなら読まない |
| 版によらず | アイテムは後の版で足したもの（クリアデータ） | ファイルの終わりなら読まない（`Items.Load`・`LoadLinkInfo`） |

# データの水準の確かめ方と組の評価（利用者向け） / Checking Your Data Against a Data Pack

> **状態: 実装前の下書き。** ここに書いた機能はまだ `srcsharp` にありません。設計は [準拠データパックに応じたバランスの検査（設計）](./balance-pack.md) にあります。実装した段階ごとに、この文書を実装に合わせて直し、[公開時に反映する場所](#公開時に反映する場所) に載せます。

データやシナリオを作る人に向けて、`srcsharp` で次の 3 つをする方法を説明します。

| したいこと | すること | 出るもの |
|---|---|---|
| [書き間違いに気づく](#書き間違いに気づく) | 何もしない（いつもの lint） | 「情報」の診断 |
| [準拠するパックの水準と比べる](#準拠するパックの水準と比べる) | `srcsharp balance Data --pack gsc-ext` | 比較のレポート（Markdown）と、パックの書き方の決まりに合わないデータの一覧 |
| [ユニットとパイロットの組を評価して遊ぶ](#ユニットとパイロットの組を評価して遊ぶ) | `srcsharp balance Data --pair パイロット名` | 組の評価のカード（Markdown） |

どれも、データを直すよう求めるものではありません。データをどうするかは作る人が決めます。

## すぐ試す

```sh
dotnet tool install -g SRCSharpTools
```

```sh
srcsharp lint path/to/scenario
```

```sh
srcsharp balance path/to/scenario/Data --output balance.md
```

```sh
srcsharp balance path/to/scenario/Data --pair "リナ＝インバース" --output card.md
```

VS Code 拡張を使っていれば、コマンドパレットからも同じことができます（[VS Code 拡張](#vs-code-拡張と-src-site-での出方)）。

## 書き間違いに気づく

`srcsharp lint`・SRC-Site のチェッカー・VS Code 拡張は、SRC の仕様と食い違うデータを「情報」として出します。情報は lint の結果（終了コード）に影響しません。今まで通っていたシナリオが、srcsharp の版を上げただけで lint に通らなくなることはありません。

| 規則 | 出る例 | 何がまずいか | 直し方 |
|---|---|---|---|
| `unit-transportation-invalid` | 移動可能地形が `陸地` | 移動可能地形に書けるのは 空・陸・水・地中・宇宙 だけ（[ユニットデータ](../../SRC.Sharp.Help/src/ユニットデータ.md) の (7)）。`陸地` は「陸」として扱われ、「地」は無視される | `陸` か `陸地中` など、意図したものに直す |
| `unit-transportation-adaption` | 移動可能地形が `空陸` なのに、地形適応が `-ABA`（空が `-`） | 空を飛べるのに、空の地形適応が「移動不可」になっている | 地形適応の空を A〜D にするか、移動可能地形から `空` を外す |

## 準拠するパックの水準と比べる

### パック

パックは、データの基準のまとまりです。srcsharp は次のパックを持っています。

| パック | 内容 |
|---|---|
| `gsc-robo` | GSC（SRC 総合支援センター）のデータパックのロボ基準 |
| `gsc-ext` | GSC のデータパックの拡張基準（等身大） |

`--pack` を省くと、シナリオが読み込む作品（`@作品名`）から自動で選びます。どれを選んだかは、レポートの最初に書かれます。ロボと拡張の両方の作品を使っていれば、作品ごとにそれぞれのパックで比べます。

### 何と何を比べるか

レポートは、自分のデータを、**同じ役割・同じ格** のパックのデータと並べます。ユニットやパイロットの妥当な数値は、主人公機かザコか、戦艦か、サポートかで大きく違うためです。役割や格を混ぜた比べ方はしません。

- **役割**は、データから自動で決めます

  | 役割 | 決め方 |
  |---|---|
  | 名前なし | パイロット名に `(ザコ)`・`(汎用)` が付いている |
  | サポート | パイロットのクラスに「サポート」が入っている |
  | 艦長・戦艦 | パイロットのクラスが「戦艦」、ユニットに特殊能力「母艦」がある |
  | 戦闘・機体 | 上のどれでもない |

- **格**（主人公格・準主役格・サブキャラ格・端役格・名前なし）はデータに書かれていないので、自動では決めません
  - [役割表](#役割表を書く) に書くと、同じ格のものと比べます
  - 書かなければ、格の代わりに **経験値**（パイロット・ユニットの、撃破されたときに相手が得る経験値）で分けます。GSC のデータでは、経験値の高いものほど能力値が高く、魂や覚醒を持つものが多い傾向があります。ただし経験値は格そのものではないので、レポートには「経験値で分けた」と書かれます
- **パイロットと乗るユニットの組**は、拡張ではユニット名とパイロット名の一致で自動で決めます（GSC の拡張では 9 割近くが一致します）。ロボでは役割表に書いたものだけです

### レポートの読み方

レポートには、層（役割・格または経験値・サイズ）ごとに次の表が出ます。

| 列 | 意味 |
|---|---|
| 層 | 何で分けたか。「格（役割表）」か「経験値 180〜199」か |
| 基準 | その層に当てはまる、文書に書かれた範囲と出典（例: データ作成ガイドライン 2.1 の主人公格）。格を役割表に書いた層にだけ出ます |
| パックの実態 | パックのデータのその層の値の広がり。P10・P50・P90 は、小さい方から 10%・50%（真ん中）・90% の位置の値です |
| あなたのデータ | 自分のデータのその層の値の広がりと、基準やパックの実態（P10〜P90）から外れたものの名前 |

例として、GSC のロボのパイロットを経験値で分けた実際の値です。

| 層 | 件数 | 格闘＋射撃（P10/P50/P90） | SP（P10/P50/P90） | 魂か覚醒を持つ |
|---|--:|---|---|--:|
| 経験値 200 以上 | 919 | 271/295/309 | 40/55/65 | 29% |
| 経験値 160〜179 | 1,482 | 256/280/295 | 40/50/60 | 10% |
| 名前なし | 931 | 230/253/281 | 0/30/40 | 1% |

自分のパイロットの経験値が 200 で、格闘＋射撃が 320 なら、同じ層のパックの P90（309）より上にある、と読めます。それが主人公の見せ場として意図したものなら、そのままで構いません。

レポートには、作品ごとの表も出ます。格（または経験値）の順に並べて、上の格なのに実効性能（最強武器の攻撃力 × 格闘・射撃の高い方）が下になっている組を示します。データ作成ガイドラインの「主人公格は実効性能が最も高い」を確かめるのに使えます。

### パックの書き方の決まり

レポートと診断には、パックの書き方の決まりに合わないデータも出ます。重さは、GSC のデータでその決まりがどれだけ守られているかで決めています。

| 規則 | パック | 重さ | 内容 | 出典 |
|---|---|---|---|---|
| `weapon-range1-infight` | ロボ・拡張 | 警告 | 射程 1 の武器に「格」がある（射程 1 は元から格闘で計算される） | 等身データ指針 |
| `weapon-range2-shooting` | ロボ・拡張 | 警告 | 射程 2 以上の武器に「射」がある（射程 2 以上は元から射撃で計算される） | 等身データ指針 |
| `weapon-range1-p` | ロボ・拡張 | 情報 | 射程 1 の武器に「Ｐ」がある（射程 1 は元から移動後に使える） | [使用可能時に関する属性](../../SRC.Sharp.Help/src/使用可能時に関する属性.md) |
| `weapon-cross-range-shooting` | ロボ・拡張 | 情報 | 射程 2 以上で「突」「武」「接」があるのに「格」「複」が無い（射撃で計算される） | 等身データ指針 |
| `weapon-beam-adaption` | ロボ | 情報 | 射程 2 以上のビーム（Ｂ）の地形適応が `AA-A`（粒子ビーム）・`AACA`（レーザー）以外 | ロボットローカルルールマニュアル |
| `weapon-beam-melee` | ロボ | 情報 | 射程 1 の武器に「Ｂ」がある（ビーム剣にはＢを付けない） | ロボットローカルルールマニュアル |
| `unit-air-adaption-nonflyer` | 拡張 | 情報 | 飛べないユニットの空の地形適応が `-`（等身大は B〜C を付ける） | 等身データ指針 |
| `name-length` | ロボ・拡張 | 情報 | パイロット愛称が 10 文字、ユニット愛称が 16 文字、武器名が 14 文字を超える（表示が崩れる） | 等身データ指針 |

規則の一覧と、使っているパックでの重さは `srcsharp balance --list-rules` で見られます。

### 役割表を書く

格・系統・乗るユニットを書いた CSV です。データの書式（unit.txt・pilot.txt）は変えません。シナリオか作品のフォルダに置き、`--roles` で指定するか、パック定義の `roles` に書きます。全員分を書く必要はありません。書いたものだけ、自動で決めたものより優先します。

```csv
種類,名前,役割,格,系統,乗るユニット
pilot,アムロ＝レイ(0079),戦闘,主人公格,,ガンダム
pilot,セイラ＝マス,戦闘,サブキャラ格,,Ｇファイター
pilot,ブライト＝ノア(0079),艦長,準主役格,,ホワイトベース
unit,ガンダム,機体,,リアル,
unit,ホワイトベース,戦艦,,,
```

| 列 | 書けるもの |
|---|---|
| 種類 | `pilot`・`unit` |
| 名前 | データの名前（括弧書きを含めてそのまま） |
| 役割 | パイロットは 戦闘・艦長・サポート・名前なし、ユニットは 機体・戦艦。空なら自動 |
| 格 | 主人公格・準主役格・サブキャラ格・端役格・名前なし（データ作成ガイドラインの 5 段階） |
| 系統 | スーパー・リアル・グレー（ユニットだけ） |
| 乗るユニット | パイロットが乗るユニットの名前。複数なら `;` で区切る |

格・系統の決め方は、[データ作成ガイドライン](https://github.com/7474/SRC-Data/blob/master/docs/%E3%83%87%E3%83%BC%E3%82%BF%E4%BD%9C%E6%88%90%E3%82%AC%E3%82%A4%E3%83%89%E3%83%A9%E3%82%A4%E3%83%B3.md) の「キャラクターの格」「ユニット系統」に従ってください。

## ユニットとパイロットの組を評価して遊ぶ

ユニットとパイロットの組を、使いどころごとに評価したカードを出します。バランスの検査ではなく、データを眺めて楽しんだり、編成を考えたりするためのものです。

```sh
srcsharp balance Data --pair "アムロ＝レイ(0079)/ガンダム"
```

```sh
srcsharp balance Data --pair "アムロ＝レイ(0079)"
```

```sh
srcsharp balance Data --pairs
```

- ユニットを省くと、拡張では名前の一致した組を評価します。ロボでは、パイロットが乗れる（クラスの合う）ユニットをすべて評価し、使いどころごとに向くユニットを並べます
- `--pairs` は、使いどころごとの上位の組と、役割が見当たらない組の一覧を出します

### カードの読み方

| 欄 | 意味 |
|---|---|
| 前提 | パック・層・パイロットのレベル（既定 30）・気力（100 と 130）・地形（既定 平地）・相手。前提が違えば値も変わります |
| 使いどころ | ボス戦・ザコ掃討・回避と囮・遊撃・長距離・支援 |
| 評価 | 同じパック・同じ役割・同じ格（または経験値）の組の中での順位。上位 5% が S、25% が A、60% が B、85% が C、ほかは D。違う層の組とは比べません |
| 主な指標 | その使いどころの評価に使った値（1 回の攻撃の期待ダメージ、倒せるザコの数、敵の命中率など） |
| 役割 | どれかの使いどころで同じ層の上位 25% に入れば「役割あり」。どれにも入らず、全部の使いどころで上回る組が同じ層にあれば「役割が見当たらない」として、その組を示します |
| 似た組 | 評価の近い組。同じ作品の中とパックの中から 3 つずつ |

値は、ゲームと同じ計算（命中率・ダメージ・クリティカル率）で出します。相手は、パックの同じ層の真ん中あたりにいる実在の組です（名前なし・同じ層・経験値 200 以上の敵の 3 種）。改造・アイテム・イベントでの強化は含めません。

| 使いどころ | 何を見るか |
|---|---|
| ボス戦 | 強い敵に、気力 130 でダメージを上げる SP を使って、1 回でどれだけ削れるか |
| ザコ掃討 | 補給なしで何体倒せるか。移動してからどれだけ攻撃できるか |
| 回避と囮 | 敵の攻撃がどれだけ当たらないか、倒されるまで何回耐えるか、反撃できない距離があるか |
| 遊撃 | 移動力と、移動してからの攻撃 |
| 長距離 | 射程 3 以上でどれだけ攻撃できるか |
| 支援 | 修理・補給、味方に効く SP、援護の特殊能力 |

`--level`・`--terrain`・`--against パイロット名/ユニット名` で前提を変えられます。

## 自分のパックを作る

作品独自の基準がある場合は、`srcsharp-pack.json` をシナリオのフォルダに置きます。srcsharp は、データのあるフォルダから上へこのファイルを探して使います。

```json
{
  "name": "シナリオ独自",
  "extends": ["gsc-robo"],
  "roles": "roles.csv",
  "ignoreWeaponAttributes": ["延"],
  "rules": {
    "weapon-beam-adaption": "off"
  }
}
```

| 項目 | 意味 |
|---|---|
| `extends` | 引き継ぐパック |
| `roles` | 役割表 |
| `ignoreWeaponAttributes` | 作品独自の武器属性。規則の判定で無いものとして扱います |
| `rules` | 規則ごとの設定。`"off"` で使わない |

ほかに書けるもの（範囲、数値の基準、SP の組み合わせ）は、[設計](./balance-pack.md#パック定義json) を参照してください。

## VS Code 拡張と SRC-Site での出方

| 場所 | 出るもの |
|---|---|
| `srcsharp`（コマンドライン） | すべて |
| VS Code 拡張 | 書き間違いと、パックの書き方の決まりの診断（エディタの波線と問題パネル）。比較のレポートと組のカードは、コマンド（「バランスレポート」「組を評価」）で開きます |
| SRC-Site のチェッカー（投稿の前の検査） | 書き間違いと、パックの書き方の決まりの診断だけ。比較のレポートと組の評価は出ません |

CI で使うときは、`--format sarif` で GitHub のコードスキャンに渡せます。警告以上で CI を止めたいときは `--fail-on warning` を付けます（既定では止めません）。

## よくある質問

**警告や情報が出たら直さないといけませんか。**
いいえ。意図したものならそのままで構いません。決まりの外れは GSC のデータにも少しあります。意図して外したユニットやパイロットは、パック定義の `exclude` に書けば出なくなります。

**数値がパックの P90 を超えていました。強すぎますか。**
それだけでは分かりません。同じ層（同じ役割・格）の中での位置を示しているだけです。役割表を書いていなければ、経験値で分けているので、格の違うものと比べている場合があります。主人公機の見せ場など、意図があるならそのままで構いません。

**経験値を変えると、比べる相手が変わりますか。**
役割表が無いときは変わります。経験値で層を分けているためです。格で比べたいときは役割表を書いてください。

**ロボダンなど、GSC 以外の基準で比べられますか。**
srcsharp には入っていません。その作品の基準を `srcsharp-pack.json` に書けば比べられます。

## 言葉

| 言葉 | 意味 |
|---|---|
| パック | データの基準のまとまり（`gsc-robo`・`gsc-ext`・自分で書いたもの） |
| 役割 | 戦闘・艦長・サポート・名前なし（パイロット）、機体・戦艦（ユニット） |
| 格 | 主人公格・準主役格・サブキャラ格・端役格・名前なし |
| 系統 | スーパー・リアル・グレー（ユニット） |
| 役割表 | 格・系統・乗るユニットを書いた CSV |
| 層 | 比べる単位。パック・役割・格（または経験値）・サイズの組み合わせ |
| P10・P50・P90 | 小さい方から 10%・50%・90% の位置の値。P10〜P90 に、層の真ん中の 8 割が入る |
| 組 | パイロットと、そのパイロットが乗るユニット |
| 実効性能 | ユニットの最強武器の攻撃力 × パイロットの格闘・射撃の高い方。データ作成ガイドラインの「実効性能を決める要素」の第一 |

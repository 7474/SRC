# 準拠データパックの分析の試作結果 / Data-Pack Analysis Prototype Results

- 状態: 試作の結果（srcsharp の機能ではない）
- 関係する Issue: https://github.com/7474/SRC/issues/1388 、https://github.com/7474/SRC/issues/1407
- 設計: [準拠データパックに応じたバランスの検査（設計）](./balance-pack.md)

設計の「役割と格の決め方」「組の評価」を作業用のプログラムで実装し、GSC データパック（7474/SRC-Data の `GSCデータパック`）の主な作品にかけた結果。設計の妥当性を確かめ、直すところを見つけるために行った。ここで見つけた課題は設計に反映した（下の「見つけた課題と設計への反映」）。

## 条件

- 作品: ロボは最終的な編成に入る機体のある作品（機動戦士ガンダム逆襲のシャア、マジンカイザー、勇者王ガオガイガー、真ゲッターロボ世界最後の日）。拡張はスレイヤーズ、ストリートファイター、るろうに剣心、ドラゴンボールＺ
- 組:
  - ロボは、役割表（試しに書いたもの。格の判定は試作者の判断）と、自動の組（名前の一致・`#推奨ユニット` のコメント・クラスの一致）。クラスの一致は、作品の中で経験値の高いパイロットから順に、乗れる（クラスの合う）ユニットのうち経験値の高いものを 1 機ずつ割り当てる（名前なしは経験値の最も低いもの）
  - 拡張は、ユニット名とパイロット名の一致。無ければ同じ作品で括弧書きを除いた名前の一致。変形・換装・ハイパーモード・他形態でたどれる形態のうち、経験値・最大攻撃力・HP の最も高いものを使う
  - 追加パイロット・暴走時パイロットとして使われるパイロットは単独では評価しない（例: ゴジータ(ＤＢＺ)・ゴテンクス(ＤＢＺ) は「ＳＰなし」の追加パイロット）
- 層: パイロットの経験値の帯（200 以上・180〜199・160〜179・120〜159・120 未満）と名前なし
- 計算: SRCCore の命中率・期待ダメージ（`UnitWeapon.HitProbability`・`ExpDamage`）。パイロットのレベル 30。地形はユニットに合わせる（陸・空なら平地、水だけなら海、宇宙だけなら宇宙）。相手との距離は武器の射程の中で最も有利なもの
- 相手:
  - ボス戦: パックの経験値 200 以上の代表（能力値が中央に近いパイロットとユニットを別々に選んで乗せたもの）。気力 130、sp.txt の効果「ダメージ増加」を持つ SP を 1 回使った倍率（1 ＋ 0.1 × レベル。魂は 3 倍）
  - ザコ掃討: パックの名前なしの代表。補給なしで 30 回行動して倒せる数（ザコの HP を減らしながら数える）
  - 回避・囮: 同じ帯の代表の組（能力値が中央に近い実在の組）。気力 100
- 評価（S〜D）: 同じ帯の組（無作為に最大 400 組）の中での順位。同じ値は平均の順位。上位 5% が S、25% が A、60% が B、85% が C、ほかは D。支援の値が 0 なら「-」
- 除外: 追加パイロットとパイロット能力付加を両方持つユニット（SRCCore が落ちる。https://github.com/7474/SRC/issues/1407 ）

| ザコ掃討が頭打ちになる | 上位の組は攻撃の上限まで 1 回 1 体倒す | 1 回の出撃に近い 30 回の行動で、ザコの HP を減らしながら数える。同じ値は平均の順位 |
| ボス戦が相手の HP で頭打ちになる | 期待ダメージを相手の HP で切ったため、強い組が同じ値に並んだ | ボス戦の期待ダメージは HP で切らない |
| ロボの比べる組が偏る | 名前の一致は勇者ロボ・使徒・怪獣などに偏り、名前なしが 2 組しかない | ロボはクラスの一致で組を作る（作品の中で経験値の順に 1 機ずつ）。役割表を推奨する |
| ロボの名前の一致が生身のユニットになる | 獅子王凱／獅子王凱 のような生身のユニットと組になる | ロボは役割表を書くのを前提にし、レポートに組の決め方を必ず出す |
| 水中・宇宙のユニットが評価できない | 平地に置くと武器が使えない | ユニットに合う地形で計算する |
| 形態の選び方 | 基本の形態や括弧書きの最初の候補と組になる | 変形・換装・ハイパーモード・他形態をたどり、最も強い形態を使う |
| 作品の中の逆転が役割を見ない | 支援役（赤法師レゾ）がボス戦の火力で逆転に挙がる | 逆転は「経験値が上の組が、下の組に全ての使いどころで並ばれるか上回られている」で判定する |
| 追加パイロット | 「ＳＰなし」のパイロットの多くは追加パイロット | 役割に「追加パイロット」を加え、単独では比べない |
| SRCCore が落ちる | 追加パイロットとパイロット能力付加を持つユニットでスタックオーバーフロー | https://github.com/7474/SRC/issues/1407 。直るまで評価から外す |

## 残る制約

- ボス戦の相手は 1 組だけなので、相手の地形適応や特殊能力（バリアなど）との相性が評価に強く出る
- ロボのクラスの一致は推定で、作品の設定と合わない組もある（司令官が機体に乗るなど）。正しくは役割表で書く
- パイロットが複数乗るユニット（ゲッターなど）は、メインパイロットだけを乗せている。サブパイロットの SP は数えていない
- SP は「ダメージ増加」の倍率だけを見ている。ひらめき・集中など、命中・回避に効く SP は含めていない

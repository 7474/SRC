# 元の SRC の動作を期待値にしたテストで移植の不具合を記録する

- 日付: 2026-10-15
- 状態: 採用

## 背景

`SRCCore` のカバレッジを上げるテストを書く際に、期待値を C# の今の動作から取ると、移植の誤りもそのまま正しいものとして固定してしまう。実際に、元の SRC（`SRC/SRC_20121125`）の動作を仕様としてテストを書くと、25 の領域から 132 件（重複をまとめて 121 件）の動作の違いが見つかった。数値の丸め（VB の Integer・Long への代入は銀行丸め、C# の `(int)` は切り捨て）、属性の組み立ての欠落、条件の反転、ループの抜け方の違いなど、同じ種類の誤りが多かった。

## 判断

- テストの期待値は元の SRC の動作から取る。各項目は元の VB のコードと照らし合わせて確かめる
- すぐに直せない違いは、期待値のテストに `[Ignore("移植の不具合: <概要>")]` を付けて残し、直したら外す
- VB の Double から Integer・Long への変換は、`(int)` ではなく `VBMath.CLng` などの既存の丸めの関数で行う

## 理由

- 不具合の一覧とテストが 1 対 1 になり、`grep` で未修正のものを数えられる
- 直したときにテストを有効にするだけで、元の SRC と同じ動作になったことを確かめられる
- 同じ種類の誤り（丸めなど）を、共通の関数に揃えることで再発させない

## 影響

- 見つかった 121 件はすべて直し、テストの `[Ignore]` を外した（7474/SRC#1215 で 57 件、続く PR で残り 64 件）
- 規約は [CONTRIBUTING.md](../../CONTRIBUTING.md) の「コードの規約」に書いている

# basic-data に外部・生成AIのマップチップを混ぜず、別のアセットパックとして扱う

- **日付**: 2026-11-18
- **状態**: 採用

## 背景

`7474/SRC#1663` では、最小の汎用データ（`SRC.Sharp/Content/basic-data`）のマップチップ番号を元の SRC の汎用グラフィック集（[マップチップの番号と意味](../assets/map-chips/README.md)）に合わせ、変種と境目の描画・自動接続（`MapAutoConnect`）を整えた。

今後の画質の向上（より高精細な画風、異なるテイスト、あるいはピクセルアート生成AIなどを用いたタイルセット）を見据え、それらの素材を `basic-data` に取り込むか別パックとして分離するかを決める必要があった。

## 判断

1. **`SRC.Sharp/Content/basic-data` には画像生成AI製のタイルや外部アセットを混ぜない**。これまでどおり Python スクリプト（`make.py`）による決定論的な手続き生成（画像は CC0 1.0、スクリプトは MIT）を保つ。
2. **高精細タイルや別画風のマップチップ集は、別のアセットパックとして作成・配布する**。配布単位を分けることで、`SRC#Web` の追加アーカイブやローカルのフォルダ配置・シナリオ同梱素材として差し替え・上書きできるようにする。
3. **別のアセットパックも [マップチップの番号と意味](../assets/map-chips/README.md) の番号規約に従う**。`SRCAuthoring.Maps.MapAutoConnect` および `SRC#Studio` は利用可能な画像番号だけを候補から選ぶ（`hasImage` によるフォールバック）ため、一部の変種や斜め境目が未作成のパックでも、基本画像（`0000.bmp`）や近傍の標準番号へ安全にフォールバックさせる。

## 理由

- **ライセンスと生成元の透明性**: `basic-data` はプログラムで再現可能かつ完全に由来が明確な CC0 1.0 素材として保つ必要がある。生成AI画像や別ライセンスの素材を混在させると、ライセンス表記・再配布の判断・再生成の保証が複雑になる。
- **リポジトリ容量とビルド速度の維持**: `basic-data` は `SRC#Web`・`SRC#Studio`・各種テストに同梱される最小構成であり、軽量・低容量であることが望ましい。
- **番号規約による差し替え互換性**: 番号の意味（例: 海の岸 `0001..0004`、深海 `0006`、道路の交差点・角 `0000..0010`、川や道路の橋 `0000..0002`, `0500..0501`）を共通の契約にすることで、どのパックでも同じ `.map` ファイル・自動接続ロジックをそのまま共有できる。

## 影響

- `basic-data` の更新は `SRC.Sharp/Content/basic-data/make.py` のみの変更で再現できる状態が保たれる。
- 新しいタイルセットやテーマ別パックを追加・公開する場合は、本リポジトリ外のアセットパックまたは別の配布ルートとし、少なくとも `0000.bmp` と実装した番号だけを置けば `SRC#` と `SRC#Studio` で動作する。
- 「ランタン号」（`SRC.Sharp/Content/lantern`）のようにシナリオ固有の素材で生成AIを使う方針とは切り離し、最小の汎用データの前提を崩さない。

# データ・シナリオの作成環境を補い、マップ作成ツールとデータの作成支援を Web の画面で作る

- 日付: 2026-11-14
- 状態: 採用（進め方は親 Issue とそのサブ Issue で追う）
- 関連: [データ検証の補強を規則の検査に絞り、作成支援ツールを収束させる](./2026-11-13-authoring-tools-convergence.md)・[データの比較を、楽しむための道具として整える](./2026-11-14-data-comparison.md)

## 背景

SRC# でデータ・シナリオを作る流れ（導入 → 素材 → 学ぶ → 始める → 書く → マップ → 試す → 検証の自動化 → 調整 → 配布）を見直した。2026-11-14 時点で次が足りない。

| 段階 | 足りないもの |
|---|---|
| 学ぶ | SRC# の道具（VS Code 拡張・デバッガ・lint・自動プレイ・Web への公開）で作る流れの説明。ヘルプの「シナリオを作成する前に」は元の SRC のまま（「メモ帳で開いて」） |
| 始める | 新しいシナリオのひな形を作る手段 |
| イベントを書く | コマンドの説明のホバー。イベントに書いたユニット・パイロット・アイテムの名前がデータにあるかの検査と、名前の補完・ホバー・定義へ移動 |
| データを書く | 書いたデータがどう見えるか・どう戦えるかをその場で確かめる手段。特殊能力・武器の属性の補完と説明 |
| マップ | 作る道具が無い。ヘルプは元の SRC の MapEdit.exe（Windows）を案内しているが、SRC# には含まれず、Mac・Linux では使えない |
| 検証の自動化 | 作者のリポジトリに置ける CI のひな形 |

## 判断

### マップ作成ツールとデータの作成支援の画面（SRC#Studio）

マップ作成ツール・データのプレビュー・表での編集などの「作成支援の画面」を **1 つの Web の画面（SRC#Studio）** として作り、**スタンドアロン（Web アプリ）と VS Code 拡張の両方** で動かす。

| 部分 | 内容 |
|---|---|
| 計算（`SRC.Sharp/SRCStudio`） | .NET の WebAssembly（SRCLintWeb と同じく、`JSExport` で JavaScript から呼ぶ。スレッド・AOT を使わない）。マップの読み書き、地形データ（`terrain.txt`）の読み込みと画像の探し方、データの読み込み（プレビュー）を SRCCore と同じ処理で行う |
| 画面 | HTML・JavaScript（モジュール）。描画は canvas。Blazor は使わない（VS Code の Webview に載せやすく、軽い） |
| ファイルの読み書き | 「場所（host）」の層に分ける。Web アプリは File System Access API（Chrome・Edge は直接読み書き。ほかのブラウザはフォルダの読み込みと、ダウンロードでの書き出し）。VS Code はカスタムエディタで、拡張がファイルを読み書きし、メッセージで画面に渡す |
| 置き場所 | Web アプリは GitHub Pages の `/SRC/studio/`。VS Code 拡張は同じ画面と WebAssembly を `.vsix` に入れる |

スタンドアロンをデスクトップのアプリにはしない。Web アプリは、インストール・コードの署名（#1438）・OS ごとの配布が要らず、更新は公開するだけで届く。Firefox・Safari は File System Access API に対応しない方針だが、どの OS でも VS Code 拡張ならファイルを直接読み書きできる。Chrome・Edge でも VS Code でもない作者に困る声が出たら、同じ画面を OS の Web 表示の部品で包むデスクトップ版を足す（画面は作り直さない）。

### データの作成支援は、テキストを主にする

データを入力欄で作る GUI（フォーム）は作らない。特殊能力・武器の属性の組み合わせは自由に近く、フォームではヘルプの仕様に追いつけない。保存し直すとコメント・行の順・書き方が崩れ、既存の作者が使えない。

テキストを唯一の元にし、画面は「見る」「確かめる」「表で直す」に絞る。

| 段階 | 支援 |
|---|---|
| 始める | ひな形と、データビューアの「このデータを元にする」 |
| 書く | 特殊能力名・武器の属性・地形適応の補完と、ヘルプの説明のホバー（LSP） |
| 見る | プレビュー（カーソルのあるユニット・パイロットの能力値・特殊能力・武器。保存しなくても変わる） |
| 比べる | 準拠するパックの同じ帯の中での位置（[データの比較](./2026-11-14-data-comparison.md) の指数） |
| 試す | 試し戦闘（小さなマップにそのユニットと相手を置くシナリオを作り、デバッガの画面付きで遊ぶ。ホットリロードで直しながら） |
| 直す | 武器・アビリティだけ、表で直せる。触っていない行はそのまま残す |

### 段階

| 段 | 内容 |
|---|---|
| 1 | ヘルプの「SRC# で作る」頁、ひな形（`srcsharp new`・VS Code のコマンド）、CI のひな形、**マップ作成ツール**（スタンドアロン・VS Code） |
| 2 | イベントの中のデータの名前の参照（診断・補完・ホバー・定義へ移動）、コマンドのホバー、特殊能力・属性の補完とホバー、データのプレビュー、試し戦闘 |
| 3 | 手元のデータでの比較、武器・アビリティの表での編集 |

確かめ方: ランタン号とは別の新しいシナリオを、ひな形からヘルプの道筋どおりに 1 話作り（マップもマップ作成ツールで作る）、CI で lint と自動プレイが通るまでを、作者の視点で確かめる。

### 作らないもの

- データのフォーム（上の理由）
- 戦闘のシミュレーション（多数回の勝率）・期待ダメージの表
- フルパッケージを取得するスクリプト
- 画面付きで遊ぶときの音（VS Code）
- データのファイルの色分け

## 理由

- 試遊・調整・配布は揃っており、足りないのは入口（学ぶ・始める）と、書いている最中の手応え（見る・試す）と、マップである。
- マップは SRC のシナリオに必須で、作る道具が無いことは他の不足より重い。
- 画面を 1 つにすれば、スタンドアロンと VS Code で機能に差が出ない。計算を SRCCore にすれば、ゲームとずれない。

## 影響

- 新しいプロジェクト `SRC.Sharp/SRCStudio` と、GitHub Pages の `/SRC/studio/` が増える。
- VS Code 拡張の `.vsix` が、SRC#Studio の WebAssembly の分だけ大きくなる。
- ヘルプの「マップデータ」は、MapEdit.exe ではなく SRC#Studio のマップ作成ツールを案内する。

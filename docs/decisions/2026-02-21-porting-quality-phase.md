# 移植を TODO の消化から品質の検証に移す

- 日付: 2026-02-21
- 状態: 採用（移植は [VB から C# への移植を完了とする](./2026-10-20-porting-complete.md) で完了）

## 背景

移植は、C# のコードに残した `// TODO` とコメントアウトした VB のコードを消化する形で進めていた。2026-02-21 の時点で、当初の 155 件以上の TODO のうち 137 件以上を解消し、残りは 18 件になっていた。残った TODO は未移植の機能ではなく、精査・最適化・設計の見直しの課題だった。

一方で、コードを移植したことと、元の SRC と同じように動くことは別の問題で、それを確かめるテストが足りなかった（当時のユニットテストは 253 メソッド。ユニットのコード 86,480 行に対してテストは 53 件）。

## 判断

- TODO の消化を移植の完了とみなし、以後は移植したコードが元の SRC と同じように動くかを確かめる作業（品質の検証）に移る
- 残った TODO は `// TODO` としてコードに残し、未移植の機能ではなく改善の課題として扱う
- 移植の精度は、ユニットテスト（関数単位）・統合テスト（イベントスクリプトの実行・セーブのラウンドトリップ）・E2E（シナリオの通しプレイと画面の比較）の 3 層で確かめる

## 理由

- TODO の残りは数が少なく、内容も機能の欠落ではなかった
- GUI を備えたゲームエンジンの移植の正しさは、ロジック・描画・スクリプトの実行をまたいで確かめないと分からず、ユニットテストだけでは足りない

## 影響

- ユニットテストを大きく増やした（`SRCCoreTests`）
- E2E は、画面を SkiaSharp で描く `SRCRender` の上でテスト用のシナリオをヘッドレスでプレイする形になった（[E2E テスト方針](../gui/e2e-testing.md)）
- 元の SRC の動作を期待値にしたテストで移植の不具合を洗い出した（[元の SRC の動作を期待値にしたテストで移植の不具合を記録する](./2026-10-15-vb-behavior-as-test-oracle.md)）

# 多言語対応

SRC# の画面の文字列（ダイアログのタイトルやボタンなど）は、日本語を既定として 15 の言語に切り替えられる。

## 仕組み

- .NET の標準の仕組み（`.resx` リソース・`System.Resources.ResourceManager`・`CultureInfo.CurrentUICulture`）を使う。
- 各プロジェクトの `Resources/Strings.resx` が既定（ニュートラル）の日本語、`Resources/Strings.<カルチャ名>.resx` が各言語。csproj で `NeutralLanguage` を `ja` にしている。各言語はサテライトアセンブリ（`<カルチャ名>/<アセンブリ名>.resources.dll`）になる。
- コードからは手書きの静的クラス `Strings`（キーごとのプロパティ）で参照する。SRCRender では `SRCCore.VB.Strings` と名前が重なるため `SRCRender.Resources.Strings` に置いている。
- 言語の設定は `SRCRender.UiLanguage.Apply(string)` で行う。設定するのは UI カルチャ（`CurrentUICulture` と `DefaultThreadCurrentUICulture`）だけで、数値の書式などに関わる `CurrentCulture` は変えない。

## 対応言語

Steam の利用者の言語の割合（[Steam ハードウェア・ソフトウェア調査](https://store.steampowered.com/hwsurvey/)、2026 年 9 月）が 0.5% 以上の言語に対応する。カルチャ名は [Steamworks の言語の一覧](https://partner.steamgames.com/doc/store/localization/languages) の Web API コードに合わせ、中国語は .NET の `zh-Hans`・`zh-Hant` にしている。一覧はコードの `SRCCore.UiLanguages.Supported` にあり、各アプリの言語の選択欄はこれを並べる。

| カルチャ名 | 言語 | Steam の割合 |
| --- | --- | --- |
| `ja` | 日本語（既定） | 2.41% |
| `en` | English | 34.20% |
| `zh-Hans` | 简体中文 | 31.39% |
| `zh-Hant` | 繁體中文 | 1.27% |
| `ko` | 한국어 | 1.37% |
| `fr` | Français | 2.08% |
| `de` | Deutsch | 2.48% |
| `es` | Español | 4.08%（中南米 0.75% も同じ訳） |
| `pt-BR` | Português (Brasil) | 3.70%（ポルトガル 0.31% も同じ訳） |
| `it` | Italiano | 0.56% |
| `ru` | Русский | 9.05% |
| `pl` | Polski | 1.49% |
| `tr` | Türkçe | 1.09% |
| `th` | ไทย | 0.82% |
| `uk` | Українська | 0.66% |

日本語・英語以外の訳は機械的に作ったもので、ネイティブの確認を経ていない。直すときは各 `*.<カルチャ名>.resx` を編集する。

## 言語の指定

| 値 | 表示 |
| --- | --- |
| 空・未指定 | 日本語（既定。OS の言語によらない） |
| 対応言語のカルチャ名 | その言語。地域違い（`en-GB`・`fr-CA`・`pt-PT` など）は同じ言語の訳、`zh-TW`・`zh-HK`・`zh-MO` は繁体字、それ以外の `zh` は簡体字 |
| `auto` | OS（ブラウザ）の UI の言語に従う。訳の無い言語は日本語 |

解釈できない値は日本語として扱う。言語の判定は ICU のデータに頼らずカルチャ名の文字列だけで行う（`SRCCore.UiLanguages.Match`）ため、WebAssembly でも同じ結果になる。

## SRC#Avalonia

設定ファイル `srcs.json`（実行ファイルと同じフォルダ）の `Option` セクションの `Language` 項目で指定する。

```json
{
  "Sections": [
    {
      "Name": "Option",
      "Items": [
        { "Name": "Language", "Value": "en" }
      ]
    }
  ]
}
```

起動時（シナリオ選択のダイアログを出す前と、`ScreenSession` が設定を読んだ直後）に反映する。変更は次回の起動から有効になる。ゲーム内の設定変更ダイアログには項目を設けていない。

## SRC#Web

シナリオ選択の画面の下にある「言語（Language）」の選択欄で切り替える。値は上の表と同じで、`auto` はブラウザの言語（`navigator.language`）に従う。カルチャを切り替えるため、ICU のデータはすべて読み込む（`BlazorWebAssemblyLoadAllGlobalizationData`）。

- 選んだ値はブラウザの localStorage（`srcweb.language`）に保存し、ページを再読み込みして切り替える。
- 利用者が選んでいなければ、サイトの設定 `srcweb.json` の `language` を既定にする（[SRC#Web を外部のサイトに置く](./gui/web-hosting.md)）。それも無ければ日本語。
- 言語は `wwwroot/index.html` が決め、環境変数 `SRCWEB_LANGUAGE`（[`configureRuntime` の `withEnvironmentVariable`](https://learn.microsoft.com/aspnet/core/blazor/fundamentals/startup#configure-the-net-webassembly-runtime)）で .NET に渡す。マルチスレッドの .NET は起動前に JS の関数を呼べない（呼ぶと「Cannot call synchronous C# methods」で起動に失敗する）ため。
- 起動時（`Program.cs` の `WebLocalization.Apply`）に `DefaultThreadCurrentUICulture` を設定するため、ゲームの画面（SRCRender の文言）にも反映する。
- .NET が動く前の読み込み中の表示も、同じ言語で出す。

訳はサテライトアセンブリにせず、`SRCSharpWeb.dll` に埋め込む（`SRCSharpWeb.csproj` の `EmbeddedResource`。SRCRender の訳も同じ）。マルチスレッドの WebAssembly では、Blazor がサテライトアセンブリを読み込む処理（ランタイムの [`loadSatelliteAssemblies`](https://github.com/dotnet/runtime/blob/release/10.0/src/mono/browser/runtime/satelliteAssemblies.ts)）がメインスレッドから C# を同期で呼び、「Cannot call synchronous C# methods」で起動に失敗するため。埋め込んだ訳は `SRCCore.EmbeddedCultureResourceManager` が引く。

文言は `SRC.Sharp/SRCSharpWeb/Resources/WebStrings.resx`（日本語）と `WebStrings.<カルチャ名>.resx` にあり、`IStringLocalizer<WebStrings>` で参照する。文字入力・ファイル選択のモーダル（`srcweb.js`）の見出しとボタンの文言も .NET 側から渡す。

## データビューア

データビューア（SRC#DataViewer）の画面の言語は、右上の歯車ボタンで開く「表示設定」の「言語（Language）」で切り替える。

- 対応言語: 上の表の言語（既定は日本語）
- 自動（ブラウザの設定）: ブラウザの言語。訳が無ければ日本語

言語を変えて「保存」すると、ページを再読み込みして切り替わる。設定は他の表示設定と同じく、ブラウザの localStorage（`dataViewerSettings`）に保存する。

切り替わるのは画面の文言（見出し・ボタン・設定・説明など）だけ。ＨＰ・装甲・格闘・射程など SRC のデータの用語や、データの中身は訳さない。

文言は `SRC.Sharp/SRCDataViewer/Resources/UIStrings.resx`（日本語）と `UIStrings.<カルチャ名>.resx` にあり、Blazor の `IStringLocalizer<UIStrings>`（コンポーネントでは `L["キー"]`）で参照する（[ASP.NET Core Blazor globalization and localization](https://learn.microsoft.com/aspnet/core/blazor/globalization-localization)）。

## srcsharp（CLI）

`srcsharp` のメッセージの言語は、オプション `--lang` か環境変数 `SRCSHARP_LANG` で切り替える。両方あれば `--lang` が優先される。値は上の表と同じ（`auto` は OS の UI の言語）。

```sh
srcsharp --lang en --help
srcsharp lint path/to/scenario --lang en
SRCSHARP_LANG=en srcsharp balance path/to/data
```

`--lang` はどのコマンドでも、引数のどこに書いてもよい。既定は OS の言語によらず日本語のため、英語の OS の CI でも出力は変わらない。

切り替わるのは使い方・件数などの人向けのメッセージだけ。SARIF・CSV・Markdown の出力、終了コード、lint の診断の文面は変わらない。従来の SRCDataLinter の出力も変わらない。

文言は `SRC.Sharp/SRCSharpTools/Resources/Strings.resx`（日本語）と `Strings.<カルチャ名>.resx` にある。Docker イメージ（`koudenpa/srcdatalinter`）では、最初の引数を `--lang` にすれば `srcsharp` が動く。

VS Code 拡張では、設定 `srcsharp.serverArgs` に `["--lang", "en"]` などを入れる（[拡張の README](../SRC.Sharp/SRCSharpVSCode/README.md#表示言語)）。切り替わるのは lint・バランスレポート・自動プレイのコマンドの出力だけで、Language Server の診断とデバッガのメッセージは訳していない。

## 訳さない文字列

次のものはシナリオやデータと結びついているため、表示言語によらず日本語のままにする。

- SRC のキーワード・データの値（陣営の「味方」「敵」、特殊能力名、地形、描画オプションの「白黒」「透過」など）。シナリオやエンジンが文字列として比較する。
- `Expression.Term(...)` で得る用語。シナリオが名称を変えられる。
- コマンド名・`CommandState` の値・リストボックスのモード指定など、エンジン内部の状態として比較する文字列。
- ステータスウィンドウやリストの見出しにある元の SRC のゲーム用語（ＨＰ・ＥＮ・装甲・運動性など）。
- フォント名（ＭＳ Ｐゴシックなど）と、「システム」などのシナリオのメッセージ。

表示文字列を状態として比較していた箇所（メッセージウィンドウの自動送りの判定、出撃選択の並べ替えボタン）は、訳しても動作が変わらないようにフラグで判定している。

## 言語を追加するには

1. `SRCCore/UiLanguages.cs` の `Supported` に、カルチャ名とその言語での名前を加える。
2. 各プロジェクト（SRCRender・SRCSharpAvalonia・SRCSharpTools・SRCSharpWeb・SRCDataViewer）の既定の resx を複製して `<名前>.<カルチャ名>.resx` を作り、`value` を訳す。キーと `{0}` などの置き換えはすべて揃える。
3. 各 csproj（SRC#Web を除く）の `SatelliteResourceLanguages` にカルチャ名を加える。SRC#Web は `*.resx` をまとめて埋め込むため変更は要らない。
4. SRC#Web の読み込み中の文言（`wwwroot/index.html` の `texts`）に訳を加える。

SRCRenderTests の `UiLanguageTests` が、1〜3 の揃い（キー・置き換え・`SatelliteResourceLanguages`）を確かめる。

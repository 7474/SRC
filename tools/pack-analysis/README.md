# 準拠データパックの分析の試作 / Data-Pack Analysis Prototype

[準拠データパックに応じたバランスの検査（設計）](../../docs/tools/balance-pack.md) の「役割と格の決め方」「組の評価」を試しに実装したもの。GSC データパックにかけた結果は [試作結果](../../docs/tools/balance-pack-analysis.md) にある。srcsharp の機能ではなく、ソリューション・CI には入れない。

## 再現

GSC データパックは [7474/SRC-Data](https://github.com/7474/SRC-Data) の `GSCデータパック` を使う。試作結果は SRC-Data のコミット `a802b31`（2026-05-06）で計測した。SRC# は、全角スペースで桁をそろえた欄と、符号の後に空白がある数値を読めるように直した版（https://github.com/7474/SRC/pull/1415 で master に入った）が要る。直す前の SRC# では、一部の武器の地形適応・クリティカル率・属性がずれて、結果が変わる。

```bash
git clone https://github.com/7474/SRC-Data ../SRC-Data
```

```bash
git -C ../SRC-Data checkout a802b31
```

```bash
dotnet build tools/pack-analysis -c Release
```

```bash
dotnet tools/pack-analysis/bin/Release/net10.0/PackAnalysis.dll ../SRC-Data/GSCデータパック/ロボ ロボ tools/pack-analysis/roles-robo.csv tools/pack-analysis/works-robo.txt > robo.md
```

```bash
dotnet tools/pack-analysis/bin/Release/net10.0/PackAnalysis.dll ../SRC-Data/GSCデータパック/拡張 拡張 tools/pack-analysis/roles-ext.csv tools/pack-analysis/works-ext.txt > ext.md
```

それぞれ 10 分ほどかかる（ロボ・拡張とも、帯ごとに最大 400 組を評価する）。標準出力に Markdown、標準エラーに進み具合と、読み込めないデータ・評価できない組を出す。

```text
PackAnalysis <パックのフォルダ> <ロボ|拡張> <役割表.csv|-> <対象作品.txt> [--sample 数] [--seed 数] [--level 数] [--tiers 格の一覧.tsv] [--cards 1]
```

| 引数 | 内容 |
|---|---|
| パックのフォルダ | `GSCデータパック/ロボ` か `GSCデータパック/拡張` |
| `ロボ`・`拡張` | 組の決め方を変える（拡張は名前の一致、ロボはクラスの一致と `#推奨ユニット`） |
| 役割表 | 下の「役割表」。使わなければ `-` |
| 対象作品 | 結果を出す作品のフォルダ名を 1 行に 1 つ。`#` で始まる行は結果の冒頭に注記として出す（選んだ根拠と出典を書く） |
| `--sample` | 帯ごとに比べる組の数（既定 400） |
| `--seed` | 比べる組を選ぶ乱数の種（既定 1） |
| `--level` | パイロットのレベル（既定 30） |
| `--tiers` | 格の一覧（`tools/pack-stats/tiers-*.tsv`）。格ごとの指数を出す |
| `--cards` | `1` で、対象作品の組ごとのデータページ（レーダーチャートと総評）を出す |

同じ SRC-Data・同じ引数なら同じ結果になる（ファイルの読み込み順と乱数の種を固定している）。

## 役割表

| 列 | 内容 |
|---|---|
| 種類 | `pilot` |
| 名前 | パイロットの名前 |
| 役割 | `戦闘`・`艦長`・`名前なし`（組にする）、`サブ`（乗るユニットにサブパイロットとして乗せる）、`ボス`（ボス戦の相手にする） |
| 格 | 主人公格・準主役格・サブキャラ格・端役格・名前なし（今は表示だけ） |
| 系統 | スーパー・リアル・グレー（今は使わない） |
| 乗るユニット | ユニットの名前。`ボス` で省くと、名前の一致などで決めた組のユニットを使う |

`#` で始まる行は読み飛ばす。

| ファイル | 内容 |
|---|---|
| `works-robo.txt` | スーパーロボット大戦シリーズの参戦回数の上位作品のうち、GSC のロボ基準にあるもの |
| `roles-robo.csv` | その作品の、最終的な編成の機体での組・サブパイロット・ボス戦の相手（6 組）。格は試作者の判断 |
| `works-ext.txt` | 原作のメディアごとの売り上げの上位作品（マンガ・ライトノベルの発行部数、ゲームの販売本数、メディアをまたいだ総収入）と、同人ゲーム・深夜アニメの代表作のうち、GSC の拡張基準にあるもの |
| `roles-ext.csv` | ボス戦の相手（マンガ 4 組・ゲーム 2 組）だけ。拡張は組を名前の一致で作る |

## 計算のあらまし

詳しくは設計と試作結果を参照。

- ゲームと同じ計算（SRCCore の `UnitWeapon.HitProbability`・`ExpDamage`）を、小さな仮のマップ（12×3）に組と相手を置いて行う。地形はユニットに合わせる
- SP は `Unit.MakeSpecialPowerInEffect` でユニットにかける（入れ子の SP も展開する）。ボス戦はダメージ・命中を上げる SP を、効果の種類ごとに最も強いものを 1 つずつ使う。回避・囮（耐久力）は、1 ターン続く回避・被ダメージ低下・装甲の SP を相手の 1 ターン（3 回の攻撃）だけ効かせ、残りの HP は SP なしで耐えるとする。一度だけ効く SP（絶対回避・被弾時の被ダメージ低下。ひらめき・忍耐 など）は使える回数を耐える回数に足す
- 評価（S〜D）は、同じ経験値の帯の組の中での順位

## 指数（実効性能と単純数字）

評価（S〜D）より細かく比べるために、使いどころごとに、同じ帯の比べる組の中央値（0 より大きい値のみ）を 100 とした指数を出す。同じ使いどころを、ゲームの計算を通した **実効性能** と、データの数字だけの **単純数字** の両方で出す。

| 指数 | 実効性能 | 単純数字 |
|---|---|---|
| 初動火力 | 気力 100・SP なしで、同じ帯の代表の組への 1 回の期待ダメージ（命中率 × ダメージ。マップ兵器を除く） | 気力の条件が 100 以下の武器の、攻撃力 × 格闘か射撃 ÷ 100 の最大 |
| ボス火力 | 気力 130 で、ダメージ・命中を上げる SP を使ったときの、ボスへの 1 回の期待ダメージ | 全ての武器（マップ兵器を除く）の、攻撃力 × 格闘か射撃 ÷ 100 の最大 |
| ザコ掃討 | 補給なしで 30 回行動して倒せる名前なしの数 | 攻撃力の高い武器から撃てる回数の分だけ 30 回まで撃った攻撃力の合計 ÷ 名前なしの HP |
| 耐久力 | 回避・被ダメージを下げる SP を使って、同じ帯の代表の組の攻撃に耐える回数（絶対回避の SP の回数を足す） | HP ÷（同じ帯の代表の組の単純なボス火力 − 装甲。最低 100） |
| 回避 | 200 − 同じ帯の代表の組の命中率（100% を超える分も数える。SP を使う） | 運動性 + パイロットの回避 |
| 遊撃 | 移動後に使える武器の期待ダメージ × 移動力 ÷ 4 | 射程 1 か Ｐ の武器の単純な火力 × 移動力 ÷ 4 |
| 長距離 | 射程 3 以上の武器の期待ダメージ | 射程 3 以上の武器の単純な火力 |
| マップ兵器 | 気力 130 で、名前なしへの 1 回の期待ダメージ × 当たる体数の目安 × 撃てる回数（3 回まで） | 単純な火力 × 当たる体数の目安 × 撃てる回数（3 回まで） |

- 実効性能は SRCCore の命中率・ダメージの計算を通すので、SP、武器の属性（Ｂ・実・貫・Ｐ など）、地形適応、パイロットの特殊能力（切り払い・Ｓ防御・底力 など）、ユニットの特殊能力（バリア・分身 など）、サイズが入る
- 単純数字は、攻撃力・HP・装甲・運動性・能力値だけを使う。格闘の値を使うのは、射程 1 で「射」が無い武器と「格」がある武器
- マップ兵器の範囲のマス数は、ヘルプの「マップ攻撃に関する属性」の図から数える。当たる体数の目安は、範囲の半分のマスに敵がいるとして最大 9 体。識が無い全方位・投下・扇・拡散は、味方を避ける分 1 体減らす
- 「実効−単純」は、両方ある指数の差の平均。正なら、データの数字より実効性能が高い（SP・属性・特殊能力が効いている）

## データページ

`--cards 1` で、組ごとに次を出す。

- レーダーチャート（Mermaid の [radar-beta](https://mermaid.js.org/syntax/radar.html)。実効性能と単純数字の 2 本を直線で結ぶ。指数 250 で頭打ち）
- 諸元（パイロットの能力値・SP、ユニットの能力値・特殊能力、武器）
- 指数の表
- 総評（強み・弱み・持たない使いどころ、実効性能と単純数字の釣り合い、ボス戦・守りで使う SP、効いている特殊能力、武器の属性、反撃できない距離、マップ兵器の型と範囲）

## 制約

- 追加パイロットとパイロット能力付加を両方持つユニットは評価しない（SRCCore が落ちる。https://github.com/7474/SRC/issues/1407 ）
- 試作なので、例外が出た組は「評価できない」として飛ばす
- 単純数字・マップ兵器の当たる体数は目安の式で、ゲームの挙動そのものではない
